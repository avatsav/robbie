EXPLANATORY PROTOTYPE · SAMPLE CONVERSATION

A marker is a checkpoint, not a message filter.

Each model request sends the whole conversation so far. A marker says: “cache everything from the start through here.”

The messages in between are included. They do not each need their own marker. Assistant replies become input on the next request, and a later marker covers them too.

Why the last message?

Its checkpoint covers every earlier message. Marking each one would be redundant for covering this request’s full prefix.

Why tools and system too?

They give the stable setup its own checkpoints, even when the task/history changes. With no earlier setup checkpoint, unchanged setup alone does not guarantee reuse.

Why not every message?

The API allows four explicit checkpoints. We normally use three. It is not a rule that assistant text is less cacheable.
